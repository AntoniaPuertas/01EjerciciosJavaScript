Módulos

A medida que un programa crece, tenerlo todo en un solo archivo se vuelve inmanejable. Los módulos permiten dividir el código en varios archivos, cada uno con una responsabilidad, y decidir qué comparte cada archivo con los demás.

Cada módulo tiene su propio ámbito: sus variables no son globales, así que no chocan con las de otros archivos. Es justo el problema que tuvimos en el tema de Arrays, donde los ejercicios tenían que ir dentro de funciones para no chocar con las variables de app.js.

Cargar un módulo

  • type="module": para que un archivo funcione como módulo, se carga con este atributo. Solo hace falta enlazar el archivo principal; los demás se cargan solos a través de sus import. 
    <script type="module" src="js/app.js"></script>
  • Qué cambia en un módulo: 
    // 1. Su propio ámbito: esta variable no es global
const mensaje = 'Solo existe en este archivo';

// 2. Modo estricto automático: sin 'use strict', esto ya es un error
// total = 5; // ReferenceError: total is not defined

// 3. Se ejecuta cuando el HTML está listo, como un script con defer

// 4. Se ejecuta una sola vez, aunque lo importen muchos archivos
  • Necesita un servidor: igual que fetch, los módulos no se cargan si abres la página con doble clic (file://). Usa WAMP, XAMPP o Live Server.

Exportar

  • Exportaciones con nombre: se pone export delante de lo que se quiere compartir. Lo que no se exporta es privado del módulo. 
    // matematicas.js
export const PI = 3.14159;

export function areaCirculo(radio) {
    return redondear(PI * radio ** 2);
}

// Privada: no se puede usar desde otros archivos
function redondear(numero) {
    return Math.round(numero * 100) / 100;
}
  • Exportar al final: también se puede escribir una lista al final del archivo, y dar otro nombre con as. 
    function sumar(a, b) { return a + b; }
function multiplicar(a, b) { return a * b; }

export { sumar, multiplicar as producto };
  • Exportación por defecto: cada módulo puede tener una sola, pensada para lo principal del archivo. 
    // saludo.js
export default function saludar(nombre) {
    return `Hola, ${nombre}`;
}

Importar

  • Importaciones con nombre: entre llaves, con el mismo nombre con el que se exportaron. Con as se les da otro nombre, por ejemplo si ya existe una variable con ese nombre. 
    import { PI, areaCirculo } from './matematicas.js';
import { producto as multiplicar } from './matematicas.js';
  • Importación por defecto: sin llaves, y con el nombre que tú elijas. 
    import saludar from './saludo.js';
import darBienvenida from './saludo.js'; // la misma función con otro nombre
  • Importar todo: con * as se reúnen todas las exportaciones en un objeto. 
    import * as mates from './matematicas.js';
console.log(mates.PI);
console.log(mates.areaCirculo(2));
  • Rutas: son relativas al archivo .js que importa (al contrario que en fetch, que son relativas a la página), empiezan por ./ o ../ y llevan la extensión .js.
  • Los import van primero: se ejecutan antes que el resto del código, estén donde estén escritos. Por convención se escriben al principio del archivo.
  • Son de solo lectura: no se puede asignar un valor nuevo a algo importado. Además, están "vivos": si el módulo cambia el valor de una variable exportada, quien la importa ve el valor nuevo. 
    import { PI } from './matematicas.js';
PI = 3; // TypeError: no se puede asignar a una importación
  • Si falla una importación, falla todo: si importas algo que el módulo no exporta, o un archivo que no existe, no se ejecuta nada del archivo. La consola indica qué falta.

Reexportar: módulos "barril"

  • Un punto de entrada único: un módulo puede reexportar lo de otros. Así, quien lo use importa todo desde un solo archivo, normalmente llamado index.js, sin saber en cuál está cada cosa. 
    // utilidades/index.js
export * from './matematicas.js';
export * from './formato.js';
export { default as saludar } from './saludo.js'; // export * no incluye la exportación por defecto

// app.js
import { areaCirculo, formatearPrecio, saludar } from './utilidades/index.js';

Importación dinámica

  • import(): carga un módulo en el momento en que hace falta, no al abrir la página. Devuelve una promesa con el módulo, así que se usa con await. Sirve para que la página cargue más rápido, dejando para después el código que quizá no se use. 
    boton.addEventListener('click', async () => {
    const { generarGrafico } = await import('./grafico.js');
    generarGrafico(datos);
});
  • await en el nivel superior: en un módulo, await se puede usar fuera de una función async. 
    // Solo en módulos
const respuesta = await fetch('datos.json');
const datos = await respuesta.json();

Novedades

  • Importar JSON (ES2025): con los atributos de importación se puede importar un archivo JSON como un módulo. Funciona en todos los navegadores principales desde 2025. El JSON solo tiene exportación por defecto. 
    import productos from './productos.json' with { type: 'json' };
console.log(productos.length);
  • Importar JSON frente a fetch: si una importación estática de JSON falla, cae todo el módulo con ella. Para datos que pueden fallar o cambiar (por ejemplo, los de un servidor), fetch sigue siendo mejor opción, porque permite controlar el error con try...catch.
  • Import maps: permiten dar un nombre corto a una ruta o a una dirección, para escribir import más cómodos. Se definen en el HTML, antes del primer módulo. 
    <script type="importmap">
{ "imports": { "utilidades": "./js/utilidades/index.js" } }
</script>

// En cualquier módulo:
import { saludar } from 'utilidades';
  • import.meta.url: la dirección completa del módulo actual. Sirve para construir rutas relativas al propio módulo, por ejemplo para usarlas con fetch. 
    const ruta = new URL('./datos.json', import.meta.url);
const respuesta = await fetch(ruta); // relativa al módulo, no a la página

Buenas prácticas

  • Un módulo, una responsabilidad: datos, formato, interfaz, cálculos... Si un archivo hace de todo, divídelo.
  • Exporta solo lo necesario: lo privado se puede cambiar sin miedo a romper otros archivos.
  • Prefiere las exportaciones con nombre: obligan a usar el mismo nombre en todo el proyecto, lo que facilita buscar dónde se usa cada cosa. Con la exportación por defecto, cada archivo puede llamarla de una forma.
  • Evita las dependencias circulares: si a.js importa b.js y b.js importa a.js, es fácil que algo no esté listo cuando se usa. Suele indicar que hay código que debería estar en un tercer módulo.

Practica

En este tema escribes código en dos sitios: los módulos de la carpeta js/modulos/ y el archivo js/ejercicios.js, que los importa. Recuerda descomentar cada import solo cuando el módulo ya exporte lo que importa. Cuando termines, compáralos con las soluciones.

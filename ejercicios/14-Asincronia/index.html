Asincronía

Hasta ahora, el código se ejecutaba línea a línea: cada instrucción esperaba a que terminara la anterior. Pero hay tareas que tardan: esperar unos segundos, pedir datos a un servidor, leer un archivo... Si JavaScript se quedara parado esperando, la página se congelaría.

El código asíncrono permite empezar una tarea lenta, seguir haciendo otras cosas y reaccionar cuando termine. Es la base de cualquier aplicación que carga datos de Internet.

Síncrono y asíncrono

  • JavaScript hace una sola cosa a la vez: cuando encarga una tarea lenta al navegador (un temporizador, una petición...), no espera; sigue con el resto del código. Cuando la tarea termina, su función se pone en una cola y se ejecuta en cuanto JavaScript queda libre. 
    console.log('1. Empiezo');

setTimeout(() => {
    console.log('3. Pasado un momento');
}, 0);

console.log('2. Termino');

// Resultado: 1. Empiezo → 2. Termino → 3. Pasado un momento
// Aunque el tiempo es 0, la función espera a que acabe el código que se está ejecutando

Temporizadores

  • setTimeout(función, milisegundos): ejecuta la función una vez, pasado ese tiempo. Devuelve un identificador que sirve para cancelarlo con clearTimeout(). 
    const aviso = setTimeout(() => {
    console.log('Han pasado 2 segundos');
}, 2000);

clearTimeout(aviso); // cancela el aviso si todavía no se ha ejecutado
  • setInterval(función, milisegundos): ejecuta la función una y otra vez, cada cierto tiempo, hasta que se detiene con clearInterval(). 
    let segundos = 0;
const reloj = setInterval(() => {
    segundos++;
    console.log(`${segundos} s`);
    if (segundos === 5) {
        clearInterval(reloj); // sin esto no pararía nunca
    }
}, 1000);

Callbacks

  • La forma antigua: al principio, las tareas asíncronas recibían una función (callback) que se llamaba al terminar. Funciona, pero cuando una tarea depende de otra, los callbacks se anidan unos dentro de otros y el código se vuelve difícil de leer y de gestionar los errores. A esto se le llama callback hell. 
    cargarUsuario(id, (usuario) => {
    cargarPedidos(usuario, (pedidos) => {
        cargarFactura(pedidos[0], (factura) => {
            console.log(factura);
            // ...y cada paso necesitaría además su propio control de errores
        });
    });
});
  • Las promesas lo resuelven, y async/await lo hace todavía más legible.

Promesas

  • Qué es una promesa: un objeto que representa un resultado que llegará más adelante. Está en uno de estos estados: pendiente (todavía no ha terminado), cumplida (ha terminado bien y tiene un valor) o rechazada (ha fallado y tiene un error).
  • Usar una promesa: then() recibe el valor si se cumple, catch() recibe el error si se rechaza y finally() se ejecuta en los dos casos. 
    fetch('datos.json')
    .then(respuesta => respuesta.json())   // cada then devuelve otra promesa: se pueden encadenar
    .then(datos => console.log(datos))
    .catch(error => console.error('Algo ha fallado:', error))
    .finally(() => console.log('Petición terminada'));
  • Crear una promesa: con new Promise(). Recibe una función con dos parámetros: resolve, que se llama para cumplirla con un valor, y reject, que se llama para rechazarla con un error. 
    function esperar(ms) {
    return new Promise((resolve) => {
        setTimeout(resolve, ms);
    });
}

function comprobarEdad(edad) {
    return new Promise((resolve, reject) => {
        if (edad >= 18) {
            resolve('Acceso permitido');
        } else {
            reject(new Error('Hay que ser mayor de edad'));
        }
    });
}

esperar(1000).then(() => console.log('Ha pasado 1 segundo'));

async y await

  • Código asíncrono que se lee como normal: dentro de una función marcada con async, await pausa la función hasta que la promesa termina y devuelve su valor. Mientras tanto, la página sigue funcionando. 
    async function mostrarDatos() {
    const respuesta = await fetch('datos.json');
    const datos = await respuesta.json();
    console.log(datos);
}
  • Errores con try...catch: si la promesa se rechaza, await lanza el error, que se captura con try...catch. El bloque finally se ejecuta siempre. 
    async function entrar(edad) {
    try {
        const mensaje = await comprobarEdad(edad);
        console.log(mensaje);
    } catch (error) {
        console.log(error.message); // 'Hay que ser mayor de edad'
    } finally {
        console.log('Comprobación terminada');
    }
}
  • Una función async siempre devuelve una promesa: lo que pongas en su return será el valor con el que se cumpla. Por eso, quien la llame tendrá que usar await o then().
  • await solo dentro de async: fuera de una función async da error, salvo en los scripts de tipo módulo (<script type="module">), que permiten usar await directamente.

Pedir datos con fetch

  • fetch(url): hace una petición y devuelve una promesa con la respuesta. Con response.json() (que también es asíncrono) se convierte el contenido JSON en objetos y arrays. 
    async function cargarProductos() {
    const respuesta = await fetch('../../assets/datos/productos.json');
    const productos = await respuesta.json();
    console.log(productos);
}
  • Comprueba response.ok: fetch solo se rechaza si no hay conexión. Si el servidor responde con un error, como 404 (no encontrado) o 500 (error del servidor), la promesa se cumple igualmente. Hay que mirar response.ok (o response.status) y lanzar el error a mano. 
    async function cargarJSON(url) {
    const respuesta = await fetch(url);
    if (!respuesta.ok) {
        throw new Error(`Error ${respuesta.status} al cargar ${url}`);
    }
    return respuesta.json();
}
  • Enviar datos: para enviar información a un servidor se indica el método, las cabeceras y el cuerpo convertido a JSON. 
    const respuesta = await fetch('https://api.ejemplo.com/usuarios', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ nombre: 'Ana', email: 'ana@ejemplo.com' }),
});
  • Rutas relativas a la página: la ruta de fetch se calcula desde la página HTML que está abierta, no desde el archivo .js donde está escrito.
  • Necesita un servidor: si abres la página con doble clic (la dirección empieza por file://), el navegador bloquea las peticiones por seguridad. Ábrela con WAMP, XAMPP o la extensión Live Server de VS Code. Por el mismo motivo de seguridad, un servidor solo acepta peticiones de otras webs si lo permite expresamente (lo que se conoce como CORS).

Varias promesas a la vez

  • En secuencia o en paralelo: dos await seguidos esperan uno detrás de otro. Si las tareas no dependen entre sí, es más rápido lanzarlas a la vez con Promise.all(). 
    // En secuencia: tarda lo que tarden las dos juntas
const productos = await cargarJSON('productos.json');
const categorias = await cargarJSON('categorias.json');

// En paralelo: tarda lo que tarde la más lenta
const [productos2, categorias2] = await Promise.all([
    cargarJSON('productos.json'),
    cargarJSON('categorias.json'),
]);
  • Promise.all(): se cumple cuando se cumplen todas, con sus resultados en el mismo orden. Si una falla, falla todo.
  • Promise.allSettled(): espera a que terminen todas, fallen o no, y devuelve el estado de cada una. Útil cuando quieres mostrar lo que sí se ha podido cargar. 
    const resultados = await Promise.allSettled([cargarJSON('a.json'), cargarJSON('b.json')]);
// [{ status: 'fulfilled', value: ... }, { status: 'rejected', reason: Error }]
  • Promise.race(): termina con la primera que termine, se cumpla o se rechace. Se usa, por ejemplo, para poner un tiempo máximo.
  • Promise.any(): se cumple con la primera que se cumpla y solo falla si fallan todas. Útil para pedir lo mismo a varios servidores y quedarse con el más rápido.

Novedades recientes

  • AbortSignal.timeout(): cancela una petición si tarda demasiado, sin tener que programarlo a mano. 
    try {
    const respuesta = await fetch(url, { signal: AbortSignal.timeout(5000) });
} catch (error) {
    if (error.name === 'TimeoutError') {
        console.log('El servidor ha tardado más de 5 segundos');
    }
}
  • Promise.withResolvers() (ES2024): crea una promesa y devuelve también sus funciones resolve y reject, para poder cumplirla o rechazarla desde fuera. Está disponible en todos los navegadores actuales. 
    const { promise, resolve } = Promise.withResolvers();
boton.addEventListener('click', () => resolve('¡Pulsado!'), { once: true });
console.log(await promise); // espera hasta que se pulse el botón
  • Promise.try() (ES2025): ejecuta una función y devuelve siempre una promesa, tanto si la función es síncrona como asíncrona, y convierte en rechazo cualquier error que lance. Todos los navegadores principales la incluyen desde enero de 2025. 
    Promise.try(() => JSON.parse(texto))   // si el texto no es JSON válido...
    .then(datos => console.log(datos))
    .catch(error => console.log('JSON incorrecto')); // ...el error llega aquí

Buenas prácticas

  • Controla siempre los errores con catch() o try...catch. Muestra al usuario un mensaje claro y deja los detalles técnicos en la consola.
  • Informa de lo que está pasando: muestra un mensaje de "Cargando..." y desactiva los botones mientras se espera, para que el usuario no los pulse varias veces.
  • Lanza en paralelo las tareas que no dependen entre sí.
  • Detén los intervalos que ya no necesites con clearInterval().
  • No olvides el await: sin él, obtienes la promesa en lugar de su valor. Si ves Promise {<pending>} en la consola, probablemente falta un await.

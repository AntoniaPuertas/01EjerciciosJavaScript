Eventos

Un evento es algo que ocurre en la página: el usuario hace clic, escribe en un campo, pulsa una tecla o envía un formulario. JavaScript puede "escuchar" esos eventos y ejecutar una función cada vez que ocurren.

Los eventos son lo que convierte una página en una aplicación interactiva: juntan todo lo visto hasta ahora (funciones, condicionales y el DOM) para responder a lo que hace el usuario.

Escuchar eventos

  • addEventListener(tipo, función): indica qué función se ejecutará cuando ocurra un evento en un elemento. A esa función se le llama listener o manejador. 
    const boton = document.querySelector('#saludar');

boton.addEventListener('click', () => {
    console.log('¡Hola!');
});
  • Se pasa la función, no se llama: si la función tiene nombre, se escribe sin paréntesis. Con paréntesis se ejecutaría en ese mismo momento, al cargar la página, en lugar de al hacer clic. 
    function saludar() {
    console.log('¡Hola!');
}
boton.addEventListener('click', saludar);    // correcto
boton.addEventListener('click', saludar());  // error: se ejecuta ya y pasa undefined
  • Evita onclick en el HTML: es posible escribir <button onclick="saludar()">, pero mezcla HTML y JavaScript y solo permite un manejador por evento. Con addEventListener el código queda en el archivo .js y se pueden añadir varios.

Eventos más habituales

  • Ratón y pantalla táctil: click, dblclick, mouseenter y mouseleave (el puntero entra o sale de un elemento). Los eventos pointerdown, pointermove y pointerup funcionan igual con ratón, dedo o lápiz.
  • Teclado: keydown (se pulsa una tecla) y keyup (se suelta). La tecla está en event.key. 
    document.addEventListener('keydown', (evento) => {
    if (evento.key === 'Escape') {
        console.log('Has pulsado Escape');
    }
});
  • Formularios: input (cambia el contenido de un campo, con cada tecla), change (se confirma un cambio: al elegir en un select o al salir de un campo), submit (se envía el formulario), focus y blur (un campo recibe o pierde el foco).
  • Página y ventana: DOMContentLoaded (el HTML ya está listo), scroll (se desplaza la página) y resize (cambia el tamaño de la ventana).

El objeto evento

  • Información sobre lo que ha pasado: el navegador pasa a la función un objeto con los detalles del evento. Por convención se llama evento, event o e. 
    campo.addEventListener('input', (evento) => {
    console.log(evento.type);         // 'input'
    console.log(evento.target);       // el elemento donde ocurrió
    console.log(evento.target.value); // lo que hay escrito en el campo
});
  • target y currentTarget: target es el elemento exacto donde ocurrió el evento (por ejemplo, un icono dentro de un botón); currentTarget es el elemento que tiene el listener.
  • preventDefault(): cancela la acción que el navegador haría por su cuenta, como seguir un enlace o recargar la página al enviar un formulario. 
    enlace.addEventListener('click', (evento) => {
    evento.preventDefault(); // el enlace ya no lleva a otra página
    console.log('Enlace pulsado');
});

Formularios

  • Escucha submit en el formulario, no el clic del botón: así también funciona cuando se pulsa Enter en un campo. Llama a preventDefault() para que la página no se recargue. 
    const formulario = document.querySelector('#registro');

formulario.addEventListener('submit', (evento) => {
    evento.preventDefault();
    console.log('Formulario enviado sin recargar la página');
});
  • FormData: recoge de una vez todos los campos que tienen atributo name. Con Object.fromEntries() se convierte en un objeto normal. 
    // <input name="nombre">  <input name="email">
const datos = Object.fromEntries(new FormData(formulario));
console.log(datos); // { nombre: 'Ana', email: 'ana@ejemplo.com' }
  • Validación con HTML: atributos como required, type="email", minlength o pattern hacen que el navegador compruebe los datos. Desde JavaScript, la propiedad validity de cada campo dice si su contenido es válido. 
    const email = formulario.elements.email;
console.log(email.validity.valid);   // false si no tiene formato de correo
console.log(formulario.checkValidity()); // true solo si todos los campos son válidos
  • reset(): vacía el formulario y deja los campos con sus valores iniciales.

Propagación y delegación de eventos

  • Los eventos "suben": cuando haces clic en un botón que está dentro de una lista, el evento se produce primero en el botón y después sube por sus antepasados: el li, el ul, el body... A esto se le llama propagación o bubbling.
  • Delegación de eventos: en lugar de poner un listener en cada botón, se pone uno solo en el contenedor y se mira con event.target qué se ha pulsado. Tiene dos ventajas: menos listeners y funciona también con los elementos que se añadan más tarde. 
    const lista = document.querySelector('#carrito');

lista.addEventListener('click', (evento) => {
    const boton = evento.target.closest('.eliminar');
    if (!boton) {
        return; // el clic no ha sido en un botón Eliminar
    }
    boton.closest('li').remove();
});
  • stopPropagation(): impide que el evento siga subiendo. Úsalo con cuidado: puede romper la delegación de otras partes de la página.

Dejar de escuchar

  • removeEventListener(): quita un listener. Necesita la misma función que se usó al añadirlo, así que no sirve con funciones escritas directamente dentro de addEventListener. 
    function mostrarPosicion(evento) {
    console.log(evento.clientX, evento.clientY);
}
document.addEventListener('pointermove', mostrarPosicion);
document.removeEventListener('pointermove', mostrarPosicion);
  • Opción once: el listener se ejecuta una sola vez y después se elimina solo. 
    boton.addEventListener('click', () => {
    console.log('Solo se muestra la primera vez');
}, { once: true });
  • AbortController: permite quitar varios listeners a la vez, aunque sus funciones no tengan nombre. 
    const controlador = new AbortController();
boton.addEventListener('click', () => console.log('clic'), { signal: controlador.signal });
campo.addEventListener('input', () => console.log('input'), { signal: controlador.signal });

controlador.abort(); // elimina los dos listeners

Accesibilidad

  • Usa <button> para todo lo que se pulsa, no un div o un span. Un botón se puede usar con el teclado (Tab para llegar y Enter o Espacio para pulsar) y los lectores de pantalla lo anuncian como botón; un div con un listener de clic, no.
  • Pon type="button" a los botones que no envían un formulario. Dentro de un form, un botón sin tipo es de tipo submit y lo enviaría.
  • Informa de los cambios: si un botón muestra u oculta contenido, actualiza su atributo aria-expanded. Los mensajes que aparecen tras una acción pueden ir en un elemento con aria-live="polite" para que el lector de pantalla los lea.
  • Asocia cada campo a su etiqueta con <label for="id-del-campo">. Además, al pulsar en la etiqueta el campo recibe el foco.

Buenas prácticas

  • Selecciona los elementos una vez, fuera del listener, y guárdalos en variables.
  • Mantén los listeners cortos: si hacen muchas cosas, mueve el trabajo a funciones con nombre.
  • Usa delegación para listas y elementos que se crean dinámicamente.
  • Valida siempre en el servidor también: la validación en el navegador mejora la experiencia, pero cualquiera puede saltársela.
